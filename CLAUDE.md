## Commands

Package manager is pnpm (`pnpm-lock.yaml`, `pnpm-workspace.yaml`).

```bash
pnpm dev          # dev server on :3000
pnpm build        # production build
pnpm lint         # eslint (flat config, no path arg needed)
pnpm test         # node --test; no test files exist yet
```

Drizzle has no package.json scripts — invoke drizzle-kit directly:

```bash
pnpm drizzle-kit generate   # diff schema vs latest snapshot, write migration
pnpm drizzle-kit migrate    # apply pending migrations
pnpm drizzle-kit studio     # browse DB
```

`pnpm dlx shadcn@latest add <component>` for UI primitives — 60 are already vendored in `components/ui/`.

## Architecture

Course platform (Udemy-like), early stage. Next.js 16.2.12 App Router, React 19, Drizzle + Postgres, Tailwind v4, shadcn/ui.

### Folder convention

`app/` holds **routes only**. Everything else is a sibling at the repo root, and `@/*` maps to that root (`@/db`, `@/schemas/course`, `@/components/ui/button`).

```
app/(public)/  app/api/    components/  components/ui/  db/  hooks/  lib/  schemas/
```

Route groups like `(public)` organize routes and allow separate layouts without appearing in the URL. Split a folder by domain (`components/course/`) only once it passes ~15 files; `features/` is premature today.

Deliberately absent: `models/` (the Drizzle schema is the model), `styles/` (Tailwind v4 theming lives in `app/globals.css` — there is no `tailwind.config`), `layouts/` (`layout.tsx` belongs to its route segment), `types/` (types are inferred: `typeof coursesTable.$inferSelect`, `z.infer<>`).

### Data flow

- **Default path:** Server Components query the DB directly ([app/(public)/courses/page.tsx](app/(public)/courses/page.tsx)). Mutations go through Server Actions.
- **`app/api/` is for HTTP clients** — the browser after first paint (search-as-you-type, polling), webhooks, external consumers. Never `fetch` your own `/api` from a Server Component; call the query function instead.
- Worked example: [app/api/courses/route.ts](app/api/courses/route.ts) (`GET` list + `POST` create, Zod-validated) and [app/api/courses/[id]/route.ts](app/api/courses/[id]/route.ts) (dynamic params).
- Zod schemas in `schemas/` are the single source of validation *and* types, shared by route handlers and (later) Server Actions.
- No HTTP client library — `fetch` is native. Reach for TanStack Query only when client-side caching/dedupe is actually needed.

### Error UI

[app/not-found.tsx](app/not-found.tsx) (404 + `notFound()`), [app/error.tsx](app/error.tsx) (segment error boundary), [app/global-error.tsx](app/global-error.tsx) (root layout crash; ships its own `<html>`/`<body>` and inline styles since it replaces the layout).

Next 16.2 renamed the recovery prop: it's `unstable_retry` (re-fetches), not `reset` (re-renders only). `error.message` is empty in production by design — only `error.digest` crosses to the client; don't "fix" this by printing the raw error.

### Migrations

drizzle-kit 1.0-rc writes **one folder per migration**: `drizzle/<timestamp>_<name>/{migration.sql,snapshot.json}`. Tutorials showing `0000_name.sql` + `meta/_journal.json` describe 0.x — not this layout. `generate` diffs the schema against the newest `snapshot.json`, not against the live DB.

Applied migrations are tracked by hash in the `drizzle.__drizzle_migrations` table. Never edit or delete a migration that has been applied — write a new one on top. `db/schema.ts` is a single file today; `schema` in [drizzle.config.ts](drizzle.config.ts) accepts a glob (`./db/schema/*.ts`) when it needs splitting.

Full drizzle-kit docs ship inside the package: `node_modules/drizzle-kit/skills/*/SKILL.md`.

### Gotchas hit in practice

- Pages reading the DB need `export const dynamic = "force-dynamic"`, or `next build` prerenders the data and bakes it in.
- Don't set `ssl` in [db/index.ts](db/index.ts) — `pg` reads `?sslmode=require` from `DATABASE_URL`. Forcing `ssl: true` breaks `next build` against local Postgres (`The server does not support SSL connections`).
- Drizzle 1.0-rc wraps driver errors in `DrizzleQueryError`; the Postgres code (e.g. `23505` unique violation) is on `error.cause`, not on the error itself.
- Route Handler `params` is a Promise; type it with the global `RouteContext<'/api/courses/[id]'>` helper (generated by `next dev`/`next build`, not imported).
- **Route language is inconsistent**: the list is `/courses` but the detail page is `/cursos/[slug]`, so `/cursos` alone 404s. Pick one language before more routes land.
- `pnpm lint` currently fails with 2 `react-hooks/set-state-in-effect` errors, both in vendored shadcn files (`components/ui/carousel.tsx`, `hooks/use-mobile.ts`) — not app code.
- `better-auth` is installed but unwired, and its peer dep wants `drizzle-orm@^0.45` while this repo runs `1.0.0-rc.4`.

## Security

`POST /api/courses` is open — no authentication, no authorization. Anyone who can reach the server can create courses. Close it before any deploy.

The same rule will apply to Server Actions: they compile to public POST endpoints reachable without the UI, so each one needs its own session check *and* an ownership check on the row it touches.
